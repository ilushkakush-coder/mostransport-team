## 1. Подготовить Apps Script

1. Откройте проект [«команда транспорта»](https://script.google.com/home/projects/19wz1vJih41gRPgmYJTjL625FLdEWuOT5933q2iffuEN89ltjpI0syiJ8/edit).
2. В файле `Код.gs` проверьте, что код сохранён и выпадающий список функций содержит `doPost`, `doGet` и `setup`.
3. Откройте **Настройки проекта → Свойства скрипта**. Свойство токена должно называться `TELEGRAM_BOT_TOKEN` без обратных кавычек; код также совместим с прежним ключом, если кавычки случайно попали в его имя. Сам токен не копируйте в HTML или GitHub.
4. Таблица уже создана функцией `setup()`. Повторный запуск использует тот же ID таблицы и обновляет список вопросов/формулы в `Summary`.

## 2. Развернуть Apps Script

1. Нажмите **Начать развертывание → Новое развертывание**.
2. Выберите тип **Веб-приложение**.
3. Для выполнения выберите **от моего имени**. Для вызова из Mini App веб-приложение должно быть доступно извне.
4. Выдайте Google разрешения, если появится запрос, затем завершите развертывание и скопируйте URL, который заканчивается на `/exec`.
5. Перед публикацией учтите: публичный URL можно вызвать из интернета, но обработчик принимает события только при действительной подписи `initData` Telegram и не старше 24 часов. В таблицу записываются Telegram ID, ID сессии, вопрос и ответ.
6. В `index.html` замените значение `PASTE_DEPLOYED_WEB_APP_URL_HERE` в `APPS_SCRIPT_URL` на скопированный URL.
7. При каждом последующем изменении Apps Script создавайте новую версию развертывания через **Управление развертываниями → Изменить → Новая версия**.

Проверка: откройте Mini App через Telegram, затем проверьте, что появилась строка во вкладке `Sessions`; сделайте пару свайпов и проверьте `Responses` и счётчики в `Summary`. Веб-запросы используют `no-cors`, поэтому интерфейс не может достоверно показать ответ Apps Script; проверяйте запись в самой таблице.

## 3. Загрузить и связать GitHub

Основная ветка репозитория `main` — источник кода и документации. Кладите изменения в корень репозитория, сохраняйте `index.html` и `transport-banner.svg` рядом.

После коммита и push на GitHub файлы в репозитории обновляются. Изменения в документации попадут в репозиторий, когда вместе с кодом будет изменён и закоммичен соответствующий Markdown-файл.

## 4. Подключить Vercel и получить сайт

1. Войдите в Vercel и импортируйте репозиторий `ilushkakush-coder/mostransport-team`.
2. Выберите основную ветку `main`, корневую папку `./`. Это статический сайт: отдельная команда сборки не нужна, точка входа — `index.html`.
3. Нажмите Deploy. После успешного первого деплоя Vercel покажет URL `*.vercel.app`.
4. Включите Git-интеграцию проекта. После этого каждый push в `main` автоматически запустит новый Production Deployment и обновит сайт по тому же URL.
5. Скопируйте URL сайта и укажите его как HTTPS-адрес Mini App в настройках Telegram-бота.

## 5. Обычный цикл обновления

1. Измените код или Markdown-документ в папке проекта.
2. Проверьте изменения в VS Code, сохраните файлы и отправьте commit/push в `main`.
3. Дождитесь статуса Ready в Vercel. Production URL останется прежним.
4. Если меняли Apps Script, отдельно обновите его развернутую версию. Одного push в GitHub недостаточно для публикации новой версии Apps Script.

## Текущие незавершённые шаги

- URL веб-приложения Apps Script пока не вставлен в `index.html`; этот URL нужен, чтобы ответы начали поступать в таблицу.
- Проект Vercel и адрес сайта пока не созданы/не получены. После подключения Vercel Git-интеграции дальнейшие push будут автоматически обновлять Production-сайт.
